## Linux 自启动总结
### 一、系统级自启动（登录前运行）
| 项目 | 内容 |
|------|------|
| **管理工具** | `systemctl` |
| **配置文件目录** | `/etc/systemd/system/`（用户自定义，优先级最高）<br>`/usr/lib/systemd/system/`（软件默认）<br>`/run/systemd/system/`（临时，重启清空） |
| **命令** | `sudo systemctl enable <服务>` 开启自启<br>`sudo systemctl disable <服务>` 关闭自启 |
| **特点** | 系统启动时运行，无需用户登录<br>以 root 或系统账户身份运行<br>适合网络服务、数据库、DNS 缓存等 |

### 二、用户级自启动（登录后运行）
| 项目 | 内容 |
|------|------|
| **规范** | XDG Autostart 规范 |
| **配置文件目录** | `~/.config/autostart/`（当前用户，优先级最高）<br>`/etc/xdg/autostart/`（所有用户） |
| **文件格式** | `.desktop` 文件 |
| **特点** | 用户登录桌面后才运行<br>以当前用户身份运行<br>适合输入法、截图工具、网盘客户端等 |

### 三、两者对比
| 对比项 | 系统级 (systemd) | 用户级 (Autostart) |
|--------|------------------|--------------------|
| **启动时机** | 开机时，登录前 | 登录桌面后 |
| **配置文件** | `.service` 文件 | `.desktop` 文件 |
| **存放目录** | `/etc/systemd/system/` | `~/.config/autostart/` |
| **管理命令** | `systemctl enable` | 图形界面“启动应用程序” |
| **典型用途** | 后台服务 | 桌面应用程序 |

### 一句话总结
> **systemd 管“电脑开机后跑什么服务”，Autostart 管“你登录后开什么软件”。**
# 操作系统自启动机制全面总结
## 一、Linux 自启动（systemd）
### 1. 系统级服务（登录前启动）
| 命令 | 作用 |
|------|------|
| `sudo systemctl enable <服务>` | 开机自启 |
| `sudo systemctl disable <服务>` | 取消开机自启 |
| `sudo systemctl status <服务>` | 查看状态 |
| `sudo systemctl start/stop <服务>` | 手动启动/停止 |

**特点**：
- 在用户登录**之前**运行
- 以 `root` 或专用系统账户运行
- 适合网络服务、数据库、DNS 缓存等
### 2. 用户级自启（登录后启动）
| 配置位置 | 说明 |
|----------|------|
| `~/.config/autostart/*.desktop` | 当前用户登录后自动运行 |
| `/etc/xdg/autostart/*.desktop` | 所有用户登录后自动运行 |

**特点**：
- 需要用户**登录桌面后**才运行
- 以**当前用户**权限运行
- 适合微信、截图工具、网盘客户端等
## 二、Windows 自启动
### 1. 开始菜单启动文件夹（用户可见，易删除）
| 路径 | 作用范围 |
|------|----------|
| `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup` | 当前用户 |
| `%PROGRAMDATA%\Microsoft\Windows\Start Menu\Programs\Startup` | 所有用户 |

### 2. 注册表（较隐蔽）
| 路径 | 作用范围 |
|------|----------|
| `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` | 当前用户 |
| `HKLM\Software\Microsoft\Windows\CurrentVersion\Run` | 所有用户 |

> 还有 `RunOnce`（仅运行一次）、`RunServices` 等变种
### 3. 任务计划程序（最隐蔽）
- 打开方式：`taskschd.msc`
- 特点：可按时间、事件、登录、解锁等**条件触发**
- 恶意软件常用此方式持久化
### 4. 服务（系统级，登录前启动）
- 打开方式：`services.msc`
- 设置为“自动”即开机自启
- 以 `SYSTEM` 或指定账户运行，权限高
### 5. 组策略登录脚本
- 打开方式：`gpedit.msc` → 用户配置 → Windows 设置 → 脚本(登录/注销)
- 主要用于企业域环境
## 三、Linux vs Windows 自启动对比
| 对比项          | Linux                       | Windows                    |
| ------------ | --------------------------- | -------------------------- |
| **系统级（登录前）** | `systemctl enable`          | 服务 (`services.msc`)        |
| **用户级（登录后）** | `~/.config/autostart/`      | 启动文件夹 / 注册表 Run            |
| **定时/条件触发**  | `cron` / `systemd timer`    | 任务计划程序                     |
| **最隐蔽方式**    | systemd service 伪装          | 任务计划程序                     |
| **查看所有自启**   | `systemctl list-unit-files` | `msconfig` / `Autoruns` 工具 |

## 四、快速查看工具
### Linux
```bash
# 查看所有系统服务自启状态
systemctl list-unit-files --type=service | grep enabled
# 查看当前用户 autostart
ls ~/.config/autostart/
```
### Windows
```cmd
msconfig          # 启动选项卡（较老，不全面）
taskmgr           # 任务管理器 → 启动（显示 Run 和 Startup Folder）
```
**最强工具**：微软官方 **Autoruns**（显示所有自启动位置，包括注册表、服务、任务计划等）
## 五、一句话总结
> **Linux：系统服务用 `systemctl enable`，用户程序用 `autostart`。**
> **Windows：注册表 Run、启动文件夹、服务、任务计划，共四大类主要位置。**
