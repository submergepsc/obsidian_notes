## 5. C 源码
`add.c`：
```c
int add(int a, int b)
{
    return a + b;
}
```
说明：
```text
该函数接收两个 int 参数 a 和 b，并返回它们的和。由于没有 main 函数，它适合用于观察单个函数对应的汇编代码。
```
## 6. x86-64 实验记录
命令：
```bash
gcc -S -O1 -o add-x86.s add.c
gcc -c -O1 -o add-x86.o add.c
file add-x86.o
objdump -d add-x86.o
```
可写结论：
```text
使用本机 gcc 编译后，目标文件显示为 x86-64 架构。反汇编中可看到 add 函数使用 x86-64 寄存器传参，返回值保存在 eax/rax 相关寄存器中。x86-64 指令长度不固定，objdump 输出中的机器码字节数可以体现这一点。
```
## 7. ARM64 实验记录
命令：
```bash
aarch64-linux-gnu-gcc -S -O1 -o add-arm64.s add.c
aarch64-linux-gnu-gcc -c -O1 -o add-arm64.o add.c
file add-arm64.o
aarch64-linux-gnu-objdump -d add-arm64.o
```
可写结论：
```text
使用 aarch64-linux-gnu-gcc 编译后，目标文件显示为 ARM aarch64 架构。生成的汇编中，add w0, w0, w1 表示将第一个参数和第二个参数相加并放回 w0，w0 同时也是 int 返回值寄存器。AArch64 常见指令长度为 4 字节，因此反汇编地址通常按 4 字节递增。
```
## 8. 对比总结模板
| 对比项 | x86-64 | ARM64/AArch64 |
| --- | --- | --- |
| 编译器 | `gcc` | `aarch64-linux-gnu-gcc` |
| 反汇编工具 | `objdump` | `aarch64-linux-gnu-objdump` |
| 文件架构 | `x86-64` | `ARM aarch64` |
| 参数寄存器 | `%rdi`, `%rsi` 等 | `w0/x0`, `w1/x1` 等 |
| 返回值寄存器 | `%eax/%rax` | `w0/x0` |
| 指令集特点 | CISC，指令长度可变 | RISC，常见指令固定 4 字节 |

## 9. 常见错误
### `aarch64-linux-gnu-gcc: command not found`
原因：没有安装交叉编译器。
解决：
```bash
sudo apt update
sudo apt install gcc-aarch64-linux-gnu
```
### `aarch64-linux-gnu-objdump: command not found`
原因：没有安装 ARM64 binutils。
解决：
```bash
sudo apt install binutils-aarch64-linux-gnu
```
### `cannot execute binary file: Exec format error`
原因：在 x86-64 主机直接运行 ARM64 程序。
解决：
```text
不要直接运行 ARM64 程序，或者使用 ARM64 环境/QEMU。
```
### `No such file or directory`
可能原因：
- 当前目录不对。
- 文件名写错。
- 编译步骤还没生成对应文件。
排查：
```bash
pwd
ls -lah
find . -name "add*"
```
### `Permission denied`
如果是脚本：
```bash
chmod +x script.sh
./script.sh
```
如果是系统目录：
```text
先确认是否需要 sudo，不要盲目修改系统文件。
```
