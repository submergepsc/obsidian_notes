# 06 C 语言到 x86 汇编
## 1. 从一个最小 C 函数开始
创建文件：
```bash
nano add.c
```
写入：
```c
int add(int a, int b)
{
    return a + b;
}
```
保存后查看：
```bash
cat add.c
```
这个文件没有 `main` 函数，所以它不能直接链接成完整可执行程序。但它非常适合观察单个函数如何变成汇编。
## 2. 使用 `gcc -S` 生成汇编
```bash
gcc -S -O1 -o add-x86.s add.c
```
解释：

| 参数 | 含义 |
| --- | --- |
| `gcc` | 本机 C 编译器 |
| `-S` | 只生成汇编文件，不生成目标文件 |
| `-O1` | 一级优化，让代码更简洁 |
| `-o add-x86.s` | 输出文件名 |
| `add.c` | 输入 C 源文件 |

查看：
```bash
less add-x86.s
```
## 3. 可能看到的 x86-64 汇编
不同 GCC 版本生成的内容可能略有不同，但核心可能类似：
```asm
add:
        leal    (%rdi,%rsi), %eax
        ret
```
解释：

| 内容 | 含义 |
| --- | --- |
| `add:` | 函数标签，表示函数入口 |
| `%rdi` | x86-64 System V ABI 中常用作第 1 个参数 |
| `%rsi` | 常用作第 2 个参数 |
| `%eax` | 常用作 32 位整数返回值 |
| `leal` | 这里用于计算加法 |
| `ret` | 函数返回 |

C 函数：
```c
int add(int a, int b)
{
    return a + b;
}
```
大致对应：
```text
a      -> %rdi 的低 32 位
b      -> %rsi 的低 32 位
返回值 -> %eax
```
## 4. 为什么是 `leal` 而不是 `add`
你可能会疑惑：明明是加法，为什么出现 `leal`？
`lea` 原本是 load effective address，用来计算地址。但 x86 允许用它做一些不访问内存的地址计算，例如：
```asm
leal (%rdi,%rsi), %eax
```
这里的意思可以理解为：
```text
%eax = %rdi + %rsi
```
编译器经常用 `lea` 做加法、乘小常数等计算，因为它不会影响标志位。
## 5. `-O0` 与 `-O1` 对比
生成无优化汇编：
```bash
gcc -S -O0 -o add-x86-O0.s add.c
```
生成一级优化汇编：
```bash
gcc -S -O1 -o add-x86-O1.s add.c
```
比较：
```bash
diff -u add-x86-O0.s add-x86-O1.s
```
`-O0` 可能看到更多内容，例如：
- 保存栈帧。
- 使用 `rbp`。
- 把参数先保存到栈上。
- 再从栈上取出来计算。
`-O1` 通常更接近“核心逻辑”。
## 6. 生成目标文件 `.o`
```bash
gcc -c -O1 -o add-x86.o add.c
```
解释：
```text
-c  只生成目标文件，不链接
```
查看文件类型：
```bash
file add-x86.o
```
可能输出：
```text
add-x86.o: ELF 64-bit LSB relocatable, x86-64, ...
```
含义：
```text
ELF             Linux 常见二进制文件格式
64-bit          64 位文件
relocatable     可重定位目标文件，还不是完整可执行程序
x86-64          目标架构
```
## 7. 使用 `objdump -d` 反汇编
```bash
objdump -d add-x86.o
```
你会看到类似：
```asm
0000000000000000 <add>:
   0:   8d 04 37                lea    (%rdi,%rsi,1),%eax
   3:   c3                      ret
```
左侧解释：
```text
0:        指令在本目标文件中的偏移地址
8d 04 37  机器码字节
lea ...   反汇编出来的汇编指令
```
x86-64 指令长度可变：
```text
lea 这条指令可能 3 字节
ret 这条指令可能 1 字节
```
这正好体现了 x86-64/CISC 的特点。
## 8. 完整程序 `hello.c`
如果想生成可运行程序，需要 `main`：
```c
#include <stdio.h>
int add(int a, int b)
{
    return a + b;
}
int main(void)
{
    int result = add(3, 4);
    printf("result = %d\n", result);
    return 0;
}
```
编译运行：
```bash
gcc -O1 -o hello-x86 hello.c
./hello-x86
```
输出：
```text
result = 7
```
反汇编完整程序：
```bash
objdump -d hello-x86 | less
```
只看某个函数附近：
```bash
objdump -d hello-x86 | grep -A20 "<add>"
objdump -d hello-x86 | grep -A40 "<main>"
```
## 9. 本节总结
记住这条主线：
```text
add.c
  -- gcc -S --> add-x86.s      汇编文本
  -- gcc -c --> add-x86.o      目标文件
  -- objdump --> 反汇编结果
```
最关键命令：
```bash
gcc -S -O1 -o add-x86.s add.c
gcc -c -O1 -o add-x86.o add.c
file add-x86.o
objdump -d add-x86.o
```
